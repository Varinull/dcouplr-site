🌐 IP, CIDR & Subnet Discovery Rules

Fleet Scout supports multiple network input formats and dynamically calculates active node allocations:

Supported Input Formats:

  • Single Server IP (e.g. 192.168.1.150): Automatically recognized as an individual standalone node (Est. Hosts = 1). Click "+ Add Single Host IP" to quickly append dedicated server rows.
  • Standard CIDR Block (e.g. 10.0.0.0/24 or 10.100.0.0/22): The engine decodes the 32-bit subnet mask, computes the total and usable IP address space (e.g. 254 hosts for a /24, 1,022 hosts for a /22), and applies enterprise density modeling.
  • Hyphenated IP Range (e.g. 192.168.1.1-192.168.1.50): Automatically computes the exact host count across the defined IP span (50 nodes).

Active Host Estimation & Manual Overrides:

Because large cloud CIDRs (e.g. /16 or /20) are rarely 100% occupied, the engine uses enterprise allocation heuristics (10%–35% active density) to prevent accidental over-licensing. You can manually override the host count at any time in the Est. Hosts input field.

Live Discovered Host Table & CSV Export:

Every discovered node is assigned a unique tracking ID (e.g. SCOUT-AWS-0001), a synthesized IP address within the target CIDR, its environment type, workload role, and runtime OS. You can search the inventory in real time or export the entire census via "📥 Export Discovered CSV".

Fleet Scout is specifically engineered for "Day -1" pre-procurement evaluations where corporate security teams and CISOs do not permit third-party agent installations or credential handoffs:

Core Security Invariants:

  • Zero Special OS Privileges (No Root / No Admin): Fleet Scout runs as a standard unprivileged user process. It does not require sudo, root, or Administrator rights.
  • Zero Node Credentials (No SSH / No Active Directory): The tool never logs into target servers. No SSH private keys, passwords, Kerberos tickets, or service account tokens are requested or stored.
  • Zero Public WAN Egress ($0.00 Egress): 100% of network decomposition, IP inventory synthesis, financial modeling, and cryptographic token derivation occurs locally inside your browser or local process memory. No packets traverse vendor WAN connections.
