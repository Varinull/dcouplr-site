🏗️ Terraform HCL to OpenTofu AST Transpiler & State Migration Guide

Wordmark & Product Identity: <dcouplr/>
Core Module: Infrastructure-as-Code (IaC) AST Transpiler & State Migration Planner
Execution Runtime: In-Memory Volatile RAM, Zero Cloud Provider API Egress
Target Output: Native OpenTofu HCL (>= 1.6.0) & Non-Destructive tofu state mv Scripts

1. Executive Summary & Zero-Downtime Migration Architecture

Migrating mission-critical enterprise cloud infrastructure from proprietary Terraform to open-source OpenTofu traditionally carries risks of destructive resource replacement (destroy-and-recreate) or state corruption.

<dcouplr/> eliminates downtime via an AST-based intermediate representation (UITGraph):

  1. Volatile AST Ingestion: TerraformHCLParser parses HCL blocks into memory without calling AWS, GCP, or Azure APIs, protecting IAM credentials and infrastructure topologies from external exposure.
  2. Deterministic Resource Mapping: Translates cloud-specific parameters (e.g., AWS EC2 t3.medium to GCP e2-medium, AWS S3 to Google Cloud Storage) using formal equivalence tables.
  3. Automated State Migration Generator: Synthesizes atomic tofu state mv blocks and tofu import shell scripts, preserving existing cloud resources in place without recreation.

2. Multi-Cloud Supported Primitives Catalog

The <dcouplr/> engine supports multi-cloud cloud primitives across AWS, GCP, and Azure:

3. Automated State Migration Plan Generation

Instead of manually editing .tfstate JSON files or risking state lock contention, <dcouplr/> generates turnkey state migration scripts:

bash
# Execute CLI state migration plan generation
dcouplr translate -i main.tf --target-provider gcp --generate-state-plan -o state_migration.sh

Generated Script Output (tofu state mv)

bash
#!/usr/bin/env bash
# Auto-generated by <dcouplr/> State Migration Engine
set -euo pipefail

echo "==> [PHASE 1] Initializing OpenTofu backend..."
tofu init

echo "==> [PHASE 2] Executing atomic non-destructive state moves..."
tofu state mv 'aws_vpc.production' 'google_compute_network.production'
tofu state mv 'aws_instance.web' 'google_compute_instance.web'
tofu state mv 'aws_db_instance.postgres' 'google_sql_database_instance.postgres'
tofu state mv 'aws_s3_bucket.assets' 'google_storage_bucket.assets'

echo "==> [PHASE 3] Validating zero plan drift..."
tofu plan -detailed-exitcode

4. Bi-Directional Graph Linking: IaC to Telemetry

<dcouplr/> links cloud infrastructure nodes directly to telemetry alerts within the unified graph:

  • A google_compute_instance node in UITGraph correlates to translated Prometheus rules (avg(system_cpu_user{instance="web"})).
  • Changes in infrastructure topology automatically alert engineers to stale Prometheus alerting queries or orphan alerts.
